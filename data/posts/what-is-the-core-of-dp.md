很多人说，动态规划的核心是状态转移方程。但我觉得不是，状态转移方程当然重要，但它只是「结果」：真正决定一道题能不能用动态规划、以及好不好写的，是你能不能找到一个**有限的状态空间**。

# 小结

- 动态规划题通常是递归题。
- 递归存在效率低、栈溢出等问题。
- 动态规划一般采用 1 到 2 个一维数组、1 个二维数组来保存前面步骤的状态，以避免重复计算。有时候还需要搭配少量变量来配合进行状态保存。
- 动态规划并不一定都能达到 O(n)。
- 动态规划的核心是有限的状态空间；要点是要对规律进行归纳总结。

# 题集

## 楼梯问题

题目：N 阶楼梯，每次可以上一阶或者两阶，求有多少种上楼梯的方法。

举例：N=4，则有 5 种方法，(1,1,1,1)、(1,2,1)、(1,1,2)、(2,1,1)、(2,2)。

思路：到达 N 阶的方式数 `W(N)`，可以拆成两个分支：一是从第 N-2 阶迈 2 阶到达 N，二是从 N-1 阶迈 1 阶到达 N。

```java
public static int dp(int stairs) {
    // 实际上，并不需要这么长的一个数组，只需要三个变量即可
	int[] status = new int[stairs + 1]; 
	for (int i = 1; i <= stairs; i++) {
		if (i == 1) {
			status[i] = 1;
			continue;
		}
		if (i == 2) {
			status[i] = 2;
			continue;
		}
		status[i] = status[i - 1] + status[i - 2];
	}
	return status[stairs];
}
```



### 楼梯问题扩展

题目：N 阶楼梯，每次可以上 1~N 阶，求有多少种上楼梯的方法。

思路：有前面的楼梯问题打底，这个问题比较容易推论：`W(n) = W(0) + W(1) + ... + W(n-1) = 2 * W(n-1)`。其中 `W(0)` 表示走到第 0 阶（即地面）的方式数，记为 1；`W(1)` 表示走到第 1 阶的方式，以此类推。为什么会等于 `2 * W(n-1)`？因为 `W(n-1)` 本身又等于 `W(0) + W(1) + ... + W(n-2)`，两者只差一个 `W(n-1)`。



## 非相邻元素最大和

题目：给定数组，求非相邻元素的最大和。

举例：数组 `{2, 9, 5, 3, 10}`，则最大和为 19。

思路：从第 1 到第 n 个元素范围中求得的最大和 `maxSum(n)`，可以拆解成两个分支：不使用第 n 个元素时，取第 1 到第 n-1 个元素范围中的最大和 `maxSum(n-1)`；使用第 n 个元素时，取第 1 到第 n-2 个元素范围中的最大和 `maxSum(n-2)` 再加上 `arr[n]`。于是 `maxSum(n) = max(maxSum(n-1), maxSum(n-2) + arr[n])`。

补充：更直观的思路，以上述数组为例 —— 如果包含第一个元素 2，则当前和为 2；如果不包含，则当前和为 0。如果包含第二个元素 9，则当前和为 9（因为不能包含 2，它们相邻）；如果不包含，则当前和为 2。以此类推：

| 数组元素 | 2 | 9 | 5 | 3 | 10 |
| --- | --- | --- | --- | --- | --- |
| 含当前元素 | 2 | 9 | 7 | 12 | 19 |
| 不含当前元素 | 0 | 2 | 9 | 9 | 12 |

```java
public static int foo(int[] arr) {
	int len = arr.length;
	int[] state = new int[len];
	state[0] = arr[0];
	state[1] = Math.max(arr[0], arr[1]);
	for (int i = 2; i < len; i++) {
		int keepCurrElement = arr[i] + state[i - 2];
		int dropCurrElement = state[i - 1];
		state[i] = Math.max(keepCurrElement, dropCurrElement);
	}
	return state[len - 1];
}
```



## 元素和为特定值

题目：给定正整数数组，给定正整数 t，是否存在元素之和为 t 的情况。

举例：数组 `{2, 9, 5, 3}`，t=10，由于 2+5+3=10，故存在。

思路：单独一个元素的状态空间只有两种：使用或不使用。但是多个元素叠加之后是指数型增长，例如第 1 个元素的可能性是 2 种，第 1~2 个元素则是 4 种（实际上会小于 4，有一些不合理分支会被剪掉），保存这类状态比较困难。

换一个思考方向：哪个状态空间是恒定的？那就是经过某一个元素之后，t 的剩余值——这个状态空间只可能落在 `[0, t]` 范围内。于是，我们对途经数组元素之后每个可能的剩余值进行标记，再据此推论途经下一个元素时剩余值的可能性。**这就是「有限状态空间」的价值：把指数级的组合，压缩成一个线性的区间。**

补充：使用动态规划能否具体给出所有组合？似乎比较困难，可能只能用递归来做。

```java
public static int foo(int[] arr, int target) {
	int len = arr.length;
    // 二维数组，第一个下标表示经过第几个数组元素，第二个下标表示t的剩余值
    // 以{2,9,5,3}，t=10为例，
    // 第一行是针对arr第一个元素2，则如果不用2，则剩余10，于是将state[0][10]置为1；
    // 如果使用2，则剩余8，于是将state[0][8]置为1。
    // 最后，我们实际上构造了一个矩阵，矩阵的每一行共有target个元素
    // 第1行表示：在处理到给定数组的第一个元素时，是否存在剩余为0的情况、是否存在剩余为1的情况、是否存在剩余为2的情况、……、是否存在剩余为target的情况
    // 第2行表示：在处理到给定数组的第二个元素时，是否存在剩余为0的情况、是否存在剩余为1的情况、是否存在剩余为2的情况、……、是否存在剩余为target的情况
    // ……
    // 第n行的计算依赖于第n-1行
	int[][] state = new int[len][target + 1];

    // 由于数组元素都是正整数，故可以进行一些剪枝操作，(如果数组存在负值，如何处理？)
	if (target >= arr[0]) {
		state[0][target - arr[0]] = 1; // include arr[0]
	}
	state[0][target] = 1; // exclude arr[0]

    int count = 0;
	for (int i = 1; i < len; i++) {
		for (int left = 0; left <= target; left++) {
			if (state[i - 1][left] == 1) {
                // 当不使用当前元素，则直接继承上一行的剩余值可能性
				state[i][left] = 1; 
                // 当剩余值小于当前值，进行剪枝，忽略
                // 当剩余值不小于当前值
				if (left >= arr[i]) {
					state[i][left - arr[i]] = 1;
					// 如果题中只要求判断是否存在，则此处判断left - arr[i] == 0即可直接return
                    // 如果题中要求返回有几种组合方式，则在此处累计即可
                    if (left - arr[i] == 0) {
                        count++;
                    }
				}
			}
		}
	}

	return count;
}
```



## K 步走到指定点

问题：一条线上分布 n 个点(n>=2)，当前位于 m 点上，可以选择向左或者向右走一个点，给定步数 k，请问到达 p 点的路线有几种？注：如果位于点 1 上，那么只能向右；如果位于点 n 上，那么只能向左。

举例：n=5, m=2, p=4, k=4，则路线有 {2,3,2,3,4}、{2,3,4,5,4}、{2,1,2,3,4}、{2,3,4,3,4} 共四种。

思路：这个题在状态空间的选择上有一些类似上题。总点数 n 和总步数 k 都是恒定的，可以使用一个二维数组 `state[k][n]`（表示从 m 点走 k 步到达 p 点），以行 `state[1][i]` 为例，它表示从 m 点走一步到达点 i 的方式有几种。以该行为基础，可以依次推论出走更多步数的情况。

```java
public static int foo(int n, int m, int p, int steps) {
    // 这里用n+2是为了在矩阵的最左侧和最右侧增加“护栏”，以减少索引越界的判断
	int[][] state = new int[steps + 1][n + 2];

    // 初始化第一行
	if (m != n) {
		state[1][m + 1] = 1;
	}
	if (m != 1) {
		state[1][m - 1] = 1;
	}

	for (int s = 2; s <= steps; s++) {
		for (int i = 1; i <= n; i++) {
			if (state[s - 1][i] > 0) {
                // 达到点i的途径有两个分支：上一步是在i-1位置；或者上一步是在i+1位置
				state[s][i] = state[s - 1][i - 1] + state[s - 1][i + 1];
			}
		}
	}
	
	return state[steps][p];
}
```



# 背包问题：同一条方程，两种状态空间

上面几个题都在做同一件事：先把问题压缩到一个有限的状态集合，再让状态之间连边。0-1 背包是这件事最好的练习——它的状态空间是「容积」与「物品」的笛卡尔积，同样有限，但**从哪个方向去索引容积**，会让代码长得完全不一样。

## 题目

有 n 件物品和一个容量为 `capacity` 的背包。第 i 件物品的重量为 `w[i]`、价值为 `v[i]`。每件物品只有一件：要么整个装入，要么不装，不能只装一部分，也不能重复装。求在总重量不超过 `capacity` 的前提下，背包能装下的最大总价值。

示例：`w = [1, 3, 4, 5]`，`v = [1, 4, 5, 7]`，`capacity = 7`，答案为 9（装第 2、3 件，重量 3+4=7，价值 4+5=9）。

## 我的解法：按「剩余容量」展开

```java
public class Knapsack02 {

    @Test
    public void test() {
        int r = solution(new int[]{1, 3, 4, 5}, new int[]{1, 4, 5, 7}, 7);
        Assertions.assertEquals(9, r);
    }

    public int solution(int[] w, int[] v, int c) {
        // omit basic check
        int[][] state = new int[w.length][c+1];
        int max = 0;
        for (int j = 0; j < c + 1; j++) {
            if (j == c) {
                state[0][j] = 0;
            } else if (j == c - w[0]) {
                state[0][j] = v[0];
                max = v[0];
            } else {
                state[0][j] = -1;
            }
        }

        for (int i = 1; i < w.length; i++) {
            for (int j = 0; j < c+1; j++) {
                state[i][j]=state[i-1][j];
                if (state[i - 1][j] > -1) {
                    if (w[i] <= j) {
                        int remainingCap = j-w[i];
                        state[i][remainingCap]= Math.max(state[i-1][remainingCap], state[i-1][j]+v[i]);
                        max = Math.max(max, state[i][remainingCap]);
                    }
                }
            }
        }

        return max;
    }
}
```

这段代码的思路是：`state[i][j]` 表示处理到第 i 件物品、**剩余容量为 j** 时的最大价值。第一行只可能有两个可达状态——一件都不装（剩余 c）与装上第一件（剩余 c-w[0]），其余标成 -1，表示「这个剩余容量根本到不了」。

之后每处理一件物品，就从上一行的可达状态出发，尝试「装入当前物品」，把价值写到更小的剩余容量上。答案不落在数组的某个固定格子里，而是一路用 `max` 记录出来的——因为「剩余容量」这个方向上，最优解可能停在任何一个格子上。

## 经典解法：按「容量上限」展开

```java
public int knapsack(int[] w, int[] v, int c) {
    int n = w.length;
    // dp[i][j]：只考虑前 i 件物品、容量上限为 j 时的最大价值
    int[][] dp = new int[n + 1][c + 1];
    for (int i = 1; i <= n; i++) {
        for (int j = 0; j <= c; j++) {
            dp[i][j] = dp[i - 1][j]; // 不装第 i 件
            if (j >= w[i - 1]) {
                dp[i][j] = Math.max(dp[i][j], dp[i - 1][j - w[i - 1]] + v[i - 1]);
            }
        }
    }
    return dp[n][c];
}
```

还可以把第一维滚掉，只留容量一维。注意此时内层必须**倒序**，否则同一件物品会被重复装入：

```java
public int knapsack(int[] w, int[] v, int c) {
    int[] dp = new int[c + 1];
    for (int i = 0; i < w.length; i++) {
        for (int j = c; j >= w[i]; j--) { // 倒序：保证每件物品只用一次
            dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
        }
    }
    return dp[c];
}
```

# 最后

从楼梯到背包，套路其实是一致的：如果要记录的东西是「组合爆炸、列不完」，那就得换个坐标：就像「元素和为特定值」里，把「选过哪些元素」换成「还剩多少」。

所谓「有限状态空间」，说到底是一种把无限问题折叠成有限表格的能力。表格的每一格都对应一个可以被复用的子问题，而动态规划，不过是在这张表上按顺序填数而已。
